This guide sets you up with self-hosted voice bridging for your Fluxcord bot.

<Aside type="caution">
  Finish the [Self-hosting guide](/self-hosting/) first. Your bot needs to be
  running before you add voice.
</Aside>

<Aside type="danger" title="Important Notes">
  Fluxer does not currently support end-to-end voice encryption, that means
  Fluxcord will bridge your Discord VC **unencrypted**. Aside from that, to bridge
  voice data, **it will decrypt** DAVE-encoded data to be sent to Fluxer.

  Please make sure you have discussed this clearly with your server members,
  and add an easy-to-find disclaimer about the bridge.
</Aside>

## Prerequisites

- A working self-hosted bot from the [Self-hosting guide](/self-hosting/)
- Both Fluxer and Discord has Developer Mode enabled (go to Settings > Advanced and enable "Developer Mode")

## Enabling voice on the bot

The bot and the voice runner share a secret password so they can trust each other. You'll generate it here and reuse it in the next section.

<Steps>
1. Firstly, generate a random secret and copy the output.
   ```bash
   openssl rand -hex 32
   ```
2. Then, open your `config.js`:
   ```bash
   nano config.js # or vi, gedit, kwrite, emacs...
   ```
3. Set the secret to what you copied and enable voice:
   ```js
   RunnerSecret: "paste-the-secret-here",
   VoiceBridgingEnabled: true,
   ```
   Keep the default `RunnerWsPort` unless you know you need to change it.
4. After that, restart the bot.
   ```bash
   docker compose up -d
   ```
</Steps>

## Running the voice runner

The voice runner is a second container that sits next to your bot. It connects to the bot over a WebSocket using the secret from the previous step.

<Steps>
1. Firstly, add the voice runner to your `docker-compose.yml`. If you already used the combined file from the [Self-hosting guide](/self-hosting/), the `voice` service is already there and you can skip to step 3. Otherwise, open the file and add this under `services:`, next to your `bot` service:
   ```bash
   nano docker-compose.yml
   ```
   ```yaml
   voice:
     image: git.gay/fluxcord/voice:latest
     restart: unless-stopped
     environment:
       - CORE_WS_URL=${CORE_WS_URL:-ws://bot:8765}
       - RUNNER_SECRET=${RUNNER_SECRET:-}
       - RUNNER_REGION=${RUNNER_REGION:-}
     networks:
       - fluxcord-net
   ```
2. Then, make sure the runner is pointed at your bot. `CORE_WS_URL` is where the runner reaches the bot. It defaults to `ws://bot:8765`, which matches the bot's service name in the combined file. If your bot's service is named differently, change `bot` to match.
3. Create a `.env` file next to your `docker-compose.yml` with the same secret from the previous section:
   ```bash
   nano .env
   ```
   ```
   RUNNER_SECRET=paste-the-secret-here
   ```
4. Now, start everything.
   ```bash
   docker compose up -d
   ```
5. To check that it worked, look at the logs.
   ```bash
   docker compose logs -f
   ```
   Look for `Connected to core`. If you see that, the runner is ready. If not, the two most common causes are a `RUNNER_SECRET` that doesn't match the one in `config.js`, or a `CORE_WS_URL` that points at the wrong service name.
</Steps>

<Aside>
  If you keep the runner in its own separate compose file, it has to join the bot's network. Mark it as external in that file:
  ```yaml
  networks:
    fluxcord-net:
      external: true
      name: fluxcord-net
  ```
</Aside>

## Bridging multiple voice channels in one server

Discord only lets one bot user join one voice channel per server at a time.
So to bridge two voice channels in the same server at the same time, you need
an extra Discord application per extra channel.

<Steps>
1. Firstly, make another bot by following the Making a bot (Discord) steps on
   the [Self-hosting guide](/self-hosting/). You only need the token,
   no Message Content Intent needed. Invite it to your server with the
   View Channel, Connect, Send Messages, Use Voice Activity, and Speak permissions.
2. Then, add its token to your `config.js`:
   ```js
   DiscordVoiceTokens: [
     "VOICE_TOKEN_1",
   ],
   ```
3. After that, restart the bot.
   ```bash
   docker compose up -d
   ```
</Steps>

<Aside>
  You need one token per voice channel you want bridged at the same time in one
  server, counting the main bot. So two channels means one extra token, three
  channels means two extra tokens. If there is no free bot left, the bot will
  skip the join and log it.
</Aside>
